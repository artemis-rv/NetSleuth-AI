# DB-6: Physical PostgreSQL Schema Specification

This document translates the DB-5 Logical / ER Model into precise PostgreSQL physical specifications. It freezes all implementation-level details, ensuring that the migration step (DB-7) requires no domain design decisions.

---

## 2. PostgreSQL ID Representation (Frozen)

For every canonical ID defined in DB-5, the physical PostgreSQL type is **UUID**.
Do not use VARCHAR, TEXT, or INTEGER for primary keys or foreign keys unless explicitly defined as a soft reference targeting an external system.

**Generation Policy:**
The **application** (specifically the microservice/engine owning the entity) generates canonical UUIDs (UUIDv4). PostgreSQL stores and enforces them, but does NOT generate them by default, ensuring IDs are known to the application before insertion for complex relational trees.

## 3. Timestamp Policy (Frozen)

**Representation:** All internal and forensic timestamps use **TIMESTAMPTZ** (timestamp with time zone).
- The database physically stores the time as an absolute point (UTC internally).
- API serialization uses ISO-8601 strings (e.g., YYYY-MM-DDTHH:MM:SSZ).
- Do not mix TIMESTAMP (without time zone) or integer epochs in business tables.
- Zeek timestamps (originally epoch floats) are parsed into TIMESTAMPTZ by M1 before insertion. Precision is retained up to PostgreSQL's microsecond limit.

---

## 4. IP Address Representation (Frozen)

For network-forensics data, IP addresses use PostgreSQL's native **INET** type.
This applies to:
- intelligence.flows.src_ip
- intelligence.flows.dst_ip
- udit.audit_events.source_ip

---

## 5. Port / Protocol Representations (Frozen)

- **Ports:** Use **INTEGER**.
- **Protocols / Services:** Use **TEXT**. Do not enforce rigorous DB enums for Zeek strings (protocol, service), as network traffic may produce arbitrary dynamic values.

---

## 6. Cryptographic Hash Representation (Frozen)

**Representation:** CHAR(64) for SHA-256 hashes.
Do not store as JSON blobs or unconstrained TEXT.

**Constraint:**
CHECK (sha256 ~ '^[0-9a-f]{64}$')

*For NetSleuth V1, the algorithm is implicitly SHA-256 based on the acquisition contracts, so a separate hash_algorithm column is omitted.*

## 8. Enums and Status Values (Frozen)

**Policy:** Use **TEXT with a CHECK constraint** (or application-layer validation) rather than rigid PostgreSQL ENUM types. This allows the detection taxonomy and investigative states to evolve without complex ALTER TYPE database migrations.

**Frozen Constrained Values:**
- cquisition.acquisitions.status: CHECK (status IN ('ingesting', 'complete', 'failed', 'archived'))
- nalytics.model_runs.status: CHECK (status IN ('running', 'complete', 'failed'))
- nalytics.findings.severity: CHECK (severity IN ('low', 'medium', 'high', 'critical'))
- investigation.investigation_cases.status: CHECK (status IN ('open', 'investigating', 'review', 'closed'))
- investigation.investigation_cases.priority: CHECK (priority IN ('low', 'medium', 'high', 'critical'))
- investigation.entities.entity_type: CHECK (entity_type IN ('host', 'user', 'service', 'network', 'domain', 'external_ip'))
- custody.evidence_items.evidence_type: CHECK (evidence_type IN ('pcap', 'pcapng', 'log_file', 'report', 'exported_session', 'analyst_note'))
- custody.reports.format: CHECK (format IN ('pdf', 'json', 'html', 'zip'))
- udit.audit_events.result: CHECK (result IN ('success', 'failure', 'denied'))
- identity.case_access.access_level: CHECK (access_level IN ('read', 'write', 'admin'))
- identity.users.role: CHECK (role IN ('administrator', 'investigator', 'analyst'))

## 9. NOT NULL Rules (Frozen)

For forensic correctness, a `NULL` means "not observed/available", not "empty".

- **`acquisition.acquisitions`**: `acquisition_id`, `file_name`, `sha256`, `format`, `source_type`, `ingested_at`, `status` MUST BE `NOT NULL`.
- **`intelligence.flows`**: `flow_id`, `zeek_uid`, `acquisition_id`, `timestamp`, `src_ip`, `src_port`, `dst_ip`, `dst_port`, `protocol`, `service` MUST BE `NOT NULL`.
- **`intelligence.protocol_events`**: `event_id`, `flow_id`, `zeek_uid`, `acquisition_id`, `protocol`, `timestamp`, `protocol_data` MUST BE `NOT NULL`.
- **`analytics.findings_packages`**: `package_id`, `acquisition_id`, `source_package_id`, `analysis_engine_version`, `findings_count`, `created_at` MUST BE `NOT NULL`.
- **`analytics.findings`**: `finding_id`, `package_id`, `acquisition_id`, `activity`, `decision_state`, `detection_method`, `severity`, `anomaly_detected`, `version`, `detected_at` MUST BE `NOT NULL`.

*All rules defined in DB-5 Entity Catalog are frozen as physical NOT NULL constraints.*

## 11. FK Behavior (Frozen)

**Default:** `ON DELETE RESTRICT ON UPDATE RESTRICT`. No cascading deletes through evidence chains.

**Exceptions (Frozen):**
- `identity.case_access.user_id` -> `identity.users.user_id` : `ON DELETE CASCADE`
- `identity.case_access.case_id` -> `investigation.investigation_cases.case_id` : `ON DELETE CASCADE`

## 14. Audit-Column Policy (Frozen)

Matches DB-2 Lifecycle Rules.

- **Mutable Entities** (`investigation_cases`, `entities`, `relationships`, `behaviors`, `attack_chains`, `users`): MUST HAVE `created_at` and `updated_at`.
- **Immutable Observations** (`acquisitions`, `evidence`, `flows`, `protocol_events`, `artifacts`, `model_registry`, `findings_packages`, `findings`, `timeline_events`, `mitre_mappings`, `evidence_items`, `reports`): MUST HAVE `created_at` (or `ingested_at`/`registered_at`/`detected_at`). NO `updated_at`.
- **Append-Only Events** (`custody_events`, `audit_events`): MUST HAVE `occurred_at`. NO `updated_at`.

## 16. Evidence-to-MinIO Physical Reference (Frozen)

For MinIO-backed objects (`acquisition.evidence` and `custody.reports`), the following physical columns are required:

- `minio_bucket` (TEXT)
- `object_key` (TEXT)
- `sha256` (CHAR(64))
- `size_bytes` (BIGINT)
- `content_type` (TEXT / MIME format)
*(ETag is intentionally excluded; SHA-256 remains the authoritative integrity field).*

---

## 17. Model-Artifact References (Frozen)

To ensure reproducibility, `analytics.model_registry` includes:
- `model_name` (TEXT)
- `model_type` (TEXT)
- `version` (TEXT)
- `artifact_object_key` (TEXT) -> Points to MinIO bucket holding the serialized ML model (`.pkl`).
- `artifact_sha256` (TEXT) -> Integrity hash of the model artifact.
- `metrics` (JSONB) -> Training metrics mapping.

---

## 18. Naming Conventions (Frozen)

- **Casing**: `snake_case` globally.
- **Tables**: Plural (`flows`, `protocol_events`, `acquisitions`, `findings`).
- **Constraints**:
  - Primary Key: `pk_<table>`
  - Foreign Key: `fk_<table>__<target>`
  - Unique: `uq_<table>__<columns>`
  - Check: `ck_<table>__<rule>`
  - Index: `ix_<table>__<columns>`

---

## 19. SQL Ownership Boundaries (Frozen)

Schemas MUST explicitly own their tables. No duplicate tables across schemas. (This perfectly aligns with Section 1).

## 20. PostgreSQL Role Strategy (Design Only - Frozen)

To be implemented later:
1. **Migration Role**: `netsleuth_migrator` (DDL access only during deployment).
2. **Application Role**: `netsleuth_app` (DML access. Cannot alter tables).
3. **Investigator Role**: `netsleuth_readonly` (Select-only access for external BI/Analysis tools).
*(Superuser `postgres` will not be used by the application).*

## 21. Environment Assumptions (Frozen)

- **Local/Dev**: Single PostgreSQL instance, single MinIO instance, local persistent volumes.
- **Production (V2+)**: DB-6 schema supports HA, but migration scripts (DB-7) should assume a standard single-node PostgreSQL deployment initially without partition syntax.

---

## 22. Large-Table Policy (Frozen)

DB-6 does NOT implement partitioning.
**Partition Candidates for Future:**
- `intelligence.flows` (Trigger: >500GB, Partition by `timestamp` / month)
- `intelligence.protocol_events` (Trigger: >500GB, Partition by `timestamp` / month)
- `audit.audit_events` (Trigger: >100GB, Partition by `occurred_at` / month)
